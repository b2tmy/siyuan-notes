# Android 逆向

本笔记用于系统记录“Android 逆向”相关知识。当前已建立章节骨架，后续学习内容、实验记录、代码片段和复盘结论统一整理到本文件。

## 学习目标

建立Android 逆向的知识框架，能够解释核心概念、识别常见模式，并通过实际样本或实验进行验证。

## 章节目录

### 1. APK、DEX、ART 与 OAT

本节先明确对象、问题和证据边界。逆向分析不以“还原全部源码”为目标，而是围绕可验证问题恢复行为模型：输入如何进入程序、状态在哪里改变、关键条件如何决定后续路径。分析前先写出问题清单，并记录样本哈希、架构、工具版本和测试环境。：结论必须能回到字节、指令、调用、内存变化或输入输出。把事实、推断和待验证假设分开，能够避免过早命名和工具误判。

### 2. Manifest、资源和四大组件

分析时应先建立稳定的结构模型，再解释局部代码。围绕数据布局、控制流、调用约定、生命周期和边界条件组织证据，优先确认那些会影响后续所有判断的字段。：看到异常现象时不要只记录结果，还要追踪产生它的前置状态。一个可复现的解释应包含触发输入、关键地址、执行顺序、返回值和最终状态。

### 3. Smali 与 Java/Kotlin 反编译

识别特征只能用来提出候选假设。节区、字符串、导入、寄存器模式、异常、权限变化或运行库调用都可能提供线索，但单一特征不能直接等同于结论。：推荐使用静态证据和动态证据交叉验证：静态分析负责定位范围和关系，动态调试负责确认实际路径和运行时数据。出现矛盾时，优先保存原始字节和现场状态，再修正模型。

### 4. JNI、Native 层和 SO 分析
