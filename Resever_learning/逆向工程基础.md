# 逆向工程基础

# 逆向工程基础：从问题定义到可复现实验

## 0x00 本章定位

逆向工程不是“把二进制一键还原成源码”，而是在源码、符号或设计文档缺失时，利用文件结构、机器指令、运行时状态和输入输出，恢复足以回答具体问题的程序模型。好的逆向笔记必须同时包含对象、问题、证据、推断、验证和限制条件。

本章作为整个逆向知识库的入口，只建立通用方法论：如何描述样本、如何理解字节和地址、如何组合静态与动态分析、如何设计最小实验、如何记录证据。PE、汇编、调用约定、Windows 内部机制、脱壳和反调试等细节由其他章节继续展开。

## 0x01 先定义问题，而不是先打开工具

同一个程序可以提出完全不同的逆向问题，例如定位序列号校验、理解配置文件格式、确认崩溃原因、恢复网络协议、识别加密算法或判断某段代码是否真正执行。问题不同，所需证据、工具和停止条件也不同。

- 对象：文件、进程、模块、函数、协议消息或内存区域。
- 输入：命令行、文件、网络数据、注册表、环境变量、用户操作或时间状态。
- 目标：需要解释的返回值、分支、数据结构、算法、状态变化或外部行为。
- 证据：字节、反汇编、交叉引用、寄存器、内存快照、调用栈、日志和输入输出。
- 停止条件：已经能够稳定复现、解释关键路径，并说明尚未确认的部分。

```text
问题模板
对象：sample.exe / 函数 RVA / 输入文件
目标：解释“输入为何被接受或拒绝”
已知：架构、文件哈希、入口、关键字符串
未知：比较位置、数据变换、最终分支
验证：固定输入 + 断点 + 寄存器/内存记录
停止：能够预测至少 3 组新输入的结果
```

## 0x02 事实、推断与假设必须分栏记录

工具显示的函数名、变量类型和伪代码都可能包含自动分析结果。它们适合帮助阅读，但不能自动升级为事实。逆向报告应把“观察到什么”和“如何解释”分开。

- 事实：在 RVA 0x1234 处存在条件跳转；ZF=1 时走成功分支。
- 推断：该分支可能是校验结果判断。
- 假设：前一个 CALL 返回布尔值，函数负责验证输入。
- 验证：改变输入并记录 CALL 返回值、ZF 和后续分支是否同步变化。
- 结论：只有多组实验支持且未出现反例时，才将假设提升为当前结论。

## 0x03 二进制、十六进制和字节序

逆向分析中的最小可观察单位通常是字节。十六进制只是更紧凑的表示方式：1 个十六进制数字表示 4 bit，2 个十六进制数字表示 1 byte。地址、立即数和文件偏移常用十六进制表示，但长度、计数和十进制业务数据不应机械地转换。

```text
二进制：1011 0110
十六进制：B6
十进制：182

0x12345678 按小端序存入内存：78 56 34 12
0x12345678 按大端序存入内存：12 34 56 78
```

x86/x64 普通整数通常采用小端序，因此内存窗口中的字节顺序与人们书写数值的顺序相反。字符串按字符顺序保存，不应把整个字符串按整数端序倒置。网络协议经常使用大端序，需要结合协议字段定义判断。

### 3.1 有符号数、补码与符号扩展

同一组位模式可以按有符号或无符号解释。例如 8 位 0xFF 作为无符号数是 255，作为补码有符号数是 -1。MOVSX 执行符号扩展，MOVZX 执行零扩展；反编译器推断错误时，比较结果和边界条件会完全改变。

```text
8-bit  0xFF -> unsigned 255 / signed -1
MOVSX EAX, AL  -> 0xFFFFFFFF
MOVZX EAX, AL  -> 0x000000FF
```

## 0x04 地址的四种常见语义

看到一个十六进制数时，首先问它表示什么：文件偏移、RVA、进程虚拟地址还是普通整数。把这些概念混在一起，是初学阶段最常见且影响最大的错误。

- FOA/File Offset：字节在磁盘文件中的位置。
- RVA：相对于模块加载基址的偏移。
- VA：进程地址空间中的实际虚拟地址。
- 模块偏移：通常写成 module+0x1234，本质上是 RVA 或分析者定义的相对偏移。

```text
VA = ModuleBase + RVA
RVA = VA - ModuleBase

示例：ModuleBase = 0x00007FF700000000
RVA = 0x1234
VA  = 0x00007FF700001234
```

启用 ASLR 后，同一函数每次运行的 VA 可能变化，但 RVA 通常稳定。因此静态工具与调试器对照时，优先记录“模块名 + RVA”，不要只保存一次运行中的绝对地址。

## 0x05 CPU、寄存器和标志位的最小模型

初学阶段不需要背完全部指令，但必须理解 CPU 如何改变状态：读取寄存器或内存、执行运算、更新标志位、选择下一条指令。分析每条关键指令时，记录输入状态、输出状态和控制流影响。

- 通用寄存器：保存整数、地址、参数和临时值。
- RIP/EIP：下一条或当前相关指令位置，具体显示方式由工具决定。
- RSP/ESP：当前栈顶；错误理解栈平衡会导致调用关系全部错位。
- RBP/EBP：可能作为栈帧基准，也可能被编译器当普通寄存器使用。
- EFLAGS/RFLAGS：ZF、CF、SF、OF 等标志决定条件跳转。

```asm
cmp eax, ebx       ; 计算 eax-ebx，仅更新标志位
je  equal_path      ; ZF=1 时跳转
jb  unsigned_below  ; 无符号比较：CF=1
jl  signed_less     ; 有符号比较：SF != OF
```

同一个 CMP 后接不同条件跳转，代表不同的有符号或无符号语义。不要仅看 CMP 两侧的值判断业务含义，必须把后续跳转条件一起阅读。

## 0x06 内存模型：地址、内容、权限和生命周期

一个内存地址至少包含四个维度：它属于哪个映射区域、该区域具有什么权限、当前保存什么内容、内容在什么时候创建或失效。只记录“地址里有某个值”不足以解释程序。

- 映像区：EXE/DLL 映射产生，常包含代码、只读数据和全局变量。
- 堆：动态分配对象和缓冲区，地址与生命周期由分配器和程序逻辑决定。
- 栈：函数调用、局部变量、保存的寄存器和返回地址。
- 共享映射：文件映射、共享内存或系统提供的映射区域。
- 保护属性：R/W/X 的组合决定区域是否可读、可写和可执行。

### 6.1 指针不是对象本身

寄存器或内存中的数值只有在被用作地址并成功访问目标区域时，才可解释为指针。结构体指针、字符串指针、函数指针和句柄在数值上都可能像地址，但其解引用方式和生命周期完全不同。

```text
RCX = 0x000001F4A1200000   ; 候选对象地址
[RCX]       -> 对象首字段或虚表指针
[RCX+8]     -> 第二字段
[[RCX]+0x20] -> 先取虚表，再取某个虚函数地址
```

## 0x07 栈、函数调用和调用约定

CALL 通常保存返回位置并转移控制流，RET 取回返回位置。参数放在哪里、谁清理栈、哪些寄存器必须保留，由 ABI 和调用约定决定。具体细节在“汇编语言与调用约定”章节展开，本章先建立分析步骤。

- 进入函数前：记录调用点、参数来源和当前栈顶。
- 进入函数后：识别保存寄存器、局部变量空间和异常处理框架。
- 返回前：确认返回值位置、栈是否恢复、非易失寄存器是否还原。
- 跨调用分析：区分参数准备、函数副作用和调用后的结果判断。

```text
调用点：参数准备 -> call target -> 检查返回值
被调函数：保存现场 -> 建立局部状态 -> 核心逻辑 -> 恢复现场 -> ret
```

## 0x08 可执行文件从磁盘到进程

操作系统加载器不会把整个文件原样复制到一个连续缓冲区后直接执行。它读取格式头、预留地址空间、映射各区域、处理依赖与重定位，并设置内存权限。磁盘布局和内存布局是两个相关但不同的视图。

```text
磁盘文件
  -> 解析文件格式与架构
  -> 为映像预留地址空间
  -> 映射头和各节/段
  -> 必要时应用重定位
  -> 解析依赖与导入
  -> 初始化运行时结构
  -> TLS/初始化代码
  -> 程序入口点
```

因此，十六进制编辑器中的偏移不能直接当成调试器地址；调试器中的内存也可能已经完成重定位、导入修复、解密或运行时修改。

## 0x09 静态分析：先建立地图

静态分析的目标是建立候选地图：程序由哪些模块、节区、函数、字符串、数据结构和调用关系组成。静态结果适合快速缩小范围，但不能证明某条路径在当前环境中一定执行。

- 基础信息：哈希、架构、文件格式、编译器或运行库线索。
- 结构信息：入口点、节区、导入导出、资源、异常表和调试信息。
- 代码信息：函数边界、调用图、控制流图、交叉引用和常量。
- 数据线索：字符串、格式串、协议常量、错误码、路径和注册表键。
- 风险标记：高熵、可写可执行区域、异常入口、少量导入或可疑解密循环。

### 9.1 字符串只是入口，不是答案

找到“密码错误”“校验成功”之类字符串后，应沿交叉引用定位使用位置，再向上寻找决定该字符串是否被使用的条件，向下观察输出之后的状态变化。字符串可能是未使用资源、调试残留或多个路径共享的文本。

### 9.2 伪代码需要反向校验

反编译器会推断变量、类型、循环和结构体。对关键结论至少回到反汇编检查参数宽度、符号性、内存访问和跳转条件。变量重命名应表达证据强度，例如 candidate_length、possible_ctx，而不是过早命名为 passwordLength 或 aesContext。

## 0x0A 动态分析：验证真实路径

动态调试能观察实际执行路径、寄存器、内存、线程和系统调用。它回答的是“这次运行发生了什么”，不是“所有条件下都会发生什么”。因此动态实验必须记录输入、环境和触发步骤。

- 软件断点：修改代码字节实现，通用但可能被完整性检查发现。
- 硬件断点：利用调试寄存器监视执行、读写或访问，数量有限。
- 内存断点：适合追踪缓冲区何时被读取、写入或执行。
- API/系统调用断点：适合定位文件、网络、内存权限、进程线程和加密行为。
- 条件断点与跟踪：减少无关命中，只记录满足表达式的事件。

### 10.1 F7、F8 与运行到返回

- 步入：进入 CALL 内部，适合确认未知函数或关键算法。
- 步过：把 CALL 作为整体执行，适合跳过已知库函数，但可能错过函数内部副作用。
- 运行到返回：快速完成当前函数，前提是栈和控制流正常。
- 运行到用户代码：帮助跳过系统库，但“用户代码”的划分仍需检查。

单步不是越多越好。优先围绕关键数据设置断点，让程序运行到数据产生、变化或被消费的位置，再对小范围指令精读。

## 0x0B 静态与动态地址对齐

IDA/Ghidra 中的地址通常基于分析时基址，x64dbg 中的地址基于本次运行的模块基址。最稳妥的记录方式是 RVA，并在运行时通过 ModuleBase + RVA 换算。

```text
StaticRVA = StaticVA - StaticImageBase
RuntimeVA = RuntimeModuleBase + StaticRVA

记录格式：sample.exe + 0x2A310
而不是只记录：0x00007FF76B4CA310
```

如果在静态工具中执行 Rebase，应在笔记里记录旧基址、新基址和时间，避免后续脚本、断点列表和截图使用不同坐标系。

## 0x0C 从输入到分支：一条通用定位链

```text
输入源
 -> 读取/接收函数
 -> 长度与格式检查
 -> 复制、解码或标准化
 -> 核心计算/比较
 -> 条件标志或返回值
 -> 成功/失败分支
 -> 外部可观察结果
```

定位时可以从两端夹逼：从输入 API 向后跟踪数据流，同时从成功/失败字符串、窗口或返回码向前追踪控制流。两条路径在某个比较、返回值检查或状态字段处汇合时，通常已经接近关键逻辑。

## 0x0D 数据流与控制流分开阅读

控制流回答“执行到哪里”，数据流回答“值从哪里来、如何变化、到哪里去”。只看控制流容易在大量分支中迷失；只看数据流又可能忽略某个值仅在特定条件下有效。

- 控制流记录：函数、基本块、分支条件、循环、异常边。
- 数据流记录：定义点、使用点、复制、类型转换、编码、长度和别名。
- 状态记录：全局变量、对象字段、标志位、线程局部数据和系统资源。
- 汇合点：多个输入或分支最终影响同一返回值、字段或输出的位置。

## 0x0E 最小实验法

一次只改变一个因素，才能把结果变化归因于该因素。输入、环境、时间、网络、文件状态和线程调度都可能影响程序；实验前先固定不相关变量。

```text
实验 A：输入 = AAAA，其他条件固定
实验 B：输入 = AAAB，仅改变最后 1 字节
记录：命中断点、比较长度、寄存器、内存差异、返回值

若路径不同：继续二分定位影响位置
若路径相同：说明该字节尚未参与当前判断，或影响被后续抵消
```

- 保存原始样本并记录 SHA-256。
- 使用副本实验，避免补丁、调试器或程序自身永久修改基线。
- 每个实验写清启动参数、工作目录、输入文件和操作步骤。
- 关键地址同时记录模块名、RVA 和当次 VA。
- 保留失败实验；它们说明哪些假设已经被排除。

## 0x0F 常用工具的角色分工

- 十六进制编辑器：查看文件偏移、原始字节和结构边界。
- DIE/PE-bear/CFF Explorer：快速查看文件结构、编译器和壳线索。
- IDA/Ghidra/Binary Ninja：反汇编、反编译、交叉引用、类型和调用图。
- x64dbg/WinDbg：断点、单步、内存、线程、异常与运行时模块。
- Process Monitor/Process Explorer：文件、注册表、进程线程和句柄行为。
- Wireshark/Fiddler：网络流量和协议字段。
- Python + pefile/Capstone/Unicorn：批量解析、指令处理和可控仿真。

工具之间应共享同一组标识：文件哈希、模块名、RVA、函数名、结构体字段和实验编号。不要让每个工具形成一套无法对照的命名。

## 0x10 最小基础实验：跟踪一个整数校验

```c
int check(int value) {
    int mixed = (value ^ 0x13579BDF) + 0x2468;
    return mixed == 0x42424242;
}

int main(int argc, char **argv) {
    if (argc != 2) return 2;
    int value = strtol(argv[1], 0, 0);
    return check(value) ? 0 : 1;
}
```

- 静态：找到 main、strtol、check 和最终条件分支，给关键变量重新命名。
- 动态：分别输入 0、1 和一个候选值，在 check 入口与 CMP/Jcc 位置记录参数、计算结果和标志位。
- 地址：静态工具和调试器统一使用 module+RVA。
- 推导：根据异或和加法的逆运算计算候选输入，再运行验证。
- 复盘：写出事实、推导公式、成功输入、失败输入及工具自动分析中的错误。

## 0x11 常见误区与修正方法

- 误区：把反编译伪代码当源码。修正：关键逻辑回到指令、寄存器宽度和跳转条件。
- 误区：看到某 API 就断言存在某行为。修正：确认调用路径、参数、返回值和副作用。
- 误区：把一次动态路径当成全部路径。修正：改变输入和环境，覆盖分支并记录未触发区域。
- 误区：混淆 FOA、RVA 和 VA。修正：所有地址写明坐标系，优先记录模块名 + RVA。
- 误区：过早给函数起业务名称。修正：先用中性候选名，证据充分后再升级。
- 误区：无限单步。修正：围绕关键数据和状态变化设置断点，缩小范围后再精读。
- 误区：修改原始样本。修正：只操作副本，保留哈希和回滚路径。

## 0x13 基础学习路线

- 第一阶段：十六进制、补码、字节序、指针、栈和寄存器。
- 第二阶段：C/C++ 编译结果、常见汇编指令和调用约定。
- 第三阶段：PE 文件、进程虚拟内存、DLL 与 Windows API。
- 第四阶段：IDA/Ghidra 静态分析和 x64dbg/WinDbg 动态调试。
- 第五阶段：完成一组由易到难的自编译样本和 CrackMe，并坚持复盘。
- 第六阶段：进入编译器特征、壳、反调试、混淆、算法识别和漏洞分析。

学习顺序不是严格线性的。最有效的方法是保持一个可运行的小项目：每学习一个概念，就在源码、编译结果、静态工具和调试器中各观察一次，形成“源码—指令—内存—行为”的闭环。

## 0x14 看雪资料索引与吸收方式

## 0x16 总结

逆向工程的核心不是某个工具按钮，而是证据驱动的问题求解过程：先定义问题，建立地址和数据模型，再组合静态地图与动态路径，最后通过可重复实验修正假设。只要每个结论都能回到原始字节、指令、运行状态或输入输出，笔记就会从知识摘录变成可复用的分析能力。
