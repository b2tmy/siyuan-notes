# 09 Z3：把校验逻辑翻译成约束，而不是手撸爆破

Z3 是微软研究院的 SMT 求解器，在 CTF 逆向里它只干一件事：你已经把算法逆明白了，但输入空间大到没法爆破，于是把"输入"换成符号变量，让求解器把满足条件的值解出来。这篇只讲逆向够用的那部分：怎么建变量、怎么照抄运算、位宽和符号怎么不翻车、unsat 了怎么查。

> 看雪式原则：Z3 不负责逆算法，只负责解方程。先用已知输入把 Python 复现版跑通，再把输入换成符号变量；模型写错时求解器只会回一个 unsat，不会告诉你错在哪一行。

## 0x00 先给结论

- 适合：输入长度固定、逐字节或逐比特校验、自定义 hash、置换/矩阵、VM 题、分支密集但逻辑清楚的题。
- 不适合：能手算化简的线性方程、输入空间本来就小、依赖文件/网络/系统调用（那是 angr + unicorn 的活）。
- 固定顺序：确认长度 → 导出常量表 → Python 复现 → 输入换符号 → 加可打印约束 → 求解 → 回代原程序验证。
- Z3 与 angr 的分工：angr 自动找路径并调用 claripy/z3，Z3 用于"算法已知、只差解方程"的场合。

```python
from z3 import *

x = BitVec('x', 32)          # 32 位符号变量，等价 C 的 uint32_t
s = Solver()
s.add(x * 3 + 7 == 0x1337)

print(s.check())             # sat / unsat / unknown
print(s.model())             # [x = 1632]
print(s.model()[x].as_long())
```

- `sat`​：有解，取 ​`model()`。
- `unsat`：约束互相矛盾，通常是模型抄错、位宽不对、常量符号反了。
- `unknown`：超时或超出理论片段（非线性整数算术最容易），先设 timeout 再改模型。

## 0x02 类型与运算符对照

- `Int`​ / ​`Real`：数学整数，没有溢出，适合纯算术与矩阵；非线性乘法会很慢。
- `BitVec(n)`​：n 位位向量，等价 ​`uintN_t`​ / ​`intN_t`，逆向首选。
- `Bool`​：布尔约束，配合 ​`If`​ / ​`Implies`​ / ​`Or`。
- `Array`​：建模内存和查找表，用 ​`Select`​ / ​`Store`​ / ​`K`。

运算符对应关系：

- 四则 ​`+ - *`​，​`/`​ 和 ​`%`​ 在 BitVec 上是**有符号** ​`SDiv`​ / ​`SRem`​；无符号要用 ​`UDiv`​ / ​`URem`。
- 比较 ​`< <= > >=`​ 是**有符号**；无符号用 ​`ULT`​ / ​`ULE`​ / ​`UGT`​ / ​`UGE`。
- 右移 ​`>>`​ 是算术右移，逻辑右移用 ​`LShR`。
- 位运算 ​`& | ^ ~`​，循环移位 ​`RotateLeft`​ / ​`RotateRight`。
- 取位段 ​`Extract(hi, lo, x)`​，扩展 ​`ZeroExt(k, x)`​ / ​`SignExt(k, x)`​，拼接 ​`Concat(a, b)`。
- 常量最好定宽：​`BitVecVal(0x80, 8)`；直接写 Python int 时按位宽截断，容易踩符号坑。

## 0x03 三种典型建模

### A. 字节数组 + 链式校验（最常见）

反编译里典型长这样：​`if ((buf[i] ^ 0x11) + buf[i+1] == 0xF5)`​，一字节扣一字节，最后 ​`buf[10] == '}'`​。建模就是照抄，只把 ​`buf` 换成符号列表。

```python
from z3 import *

target = b"flag{z3_ok}"
xs = [BitVec(f"f{i}", 8) for i in range(len(target))]
s = Solver()

for x in xs:                       # 先剪枝：可打印 ASCII
    s.add(x >= 0x20, x <= 0x7e)
for i, ch in enumerate(b"flag"):   # 已知前缀
    s.add(xs[i] == ch)

s.add(xs[4] ^ BitVecVal(0x11, 8) == target[4] ^ 0x11)
s.add(xs[5] + xs[4] == target[5] + target[4])
s.add(xs[6] ^ xs[5] == target[6] ^ target[5])
s.add(xs[7] + xs[6] == target[7] + target[6])
s.add(xs[8] ^ xs[7] == target[8] ^ target[7])
s.add(xs[9] ^ xs[8] == target[9] ^ target[8])
s.add(xs[10] == target[10])

if s.check() == sat:
    m = s.model()
    print("FLAG:", bytes(m[x].as_long() for x in xs).decode())
```

注意这里的常量是从已知明文反推出来的，实际做题时直接抄二进制里的立即数。链式校验的好处是每个条件都把上一字节锁死；​`|`​、​`+` 这类条件容易留下多解，看到模型输出像乱码就先怀疑约束不够。

### B. 32 位 hash 逆推

见到 ​`h = (x ^ (x >> 16)) * 0x45D9F3B`​ 这种，直接把 4 个输入字节 ​`Concat` 成一个 32 位字，让 z3 反推。

```python
from z3 import *

def hash32(x):
    h = (x ^ LShR(x, 16)) * BitVecVal(0x45D9F3B, 32)
    return h ^ BitVecVal(0xDEADBEEF, 32)

xs = [BitVec(f"b{i}", 8) for i in range(4)]
s = Solver()
x = Concat(xs[3], xs[2], xs[1], xs[0])      # 小端：*(uint32_t*)buf
s.add(hash32(x) == BitVecVal(0x13371337, 32))

if s.check() == sat:
    m = s.model()
    print(bytes(m[b].as_long() for b in xs).hex())
```

端序写反是这类题的第一大死因：​`Concat(xs[3], xs[2], xs[1], xs[0])`​ 是小端，​`Concat(xs[0], ...)`​ 是大端，对应汇编里的 ​`mov eax, [buf]`​ 和 ​`bswap`。

### C. 整数方程、矩阵与置换

没有位运算、只有加减乘的题用 ​`Int` 更省事；矩阵乘、线性组合直接双循环。

```python
from z3 import *

a, b, c = Int('a'), Int('b'), Int('c')
s = Solver()
s.add(a + b == 12, b + c == 20, a + c == 18)
s.add(a > 0, b > 0, c > 0)
if s.check() == sat:
    m = s.model()
    print(m[a], m[b], m[c])        # 5 7 13
```

置换题（S-box、换表、魔方类）不要用 ​`If`​ 链硬查表，先把常量表在 Python 里算成数组，再用 ​`Array`​ + ​`Select`，或者干脆按已知下标逐个代入。

## 0x04 位宽、符号与溢出：翻车重灾区

- 8 位加法自动 mod 256，和 ​`uint8_t`​ 一致；但 C 里 ​`uint8_t`​ 参与运算会提升为 ​`int`​，乘法必须 ​`ZeroExt` 再乘，否则结果被截成 8 位。
- `x < 0x80`​ 在 8 位 BitVec 上是**有符号**比较，​`0x80`​ 被解释成 -128，直接 unsat；写 ​`x <= 0x7e`​ 或 ​`ULT(x, 0x80)`。
- 32 位常量参与 8 位变量运算会被截断，z3 不一定报错，只是结果悄悄错；常量一律 ​`BitVecVal(v, n)`。
- 移位量不要超过位宽；C 里是未定义行为，模型里照抄只会得到无意义解。
- 拆分与拼接用 ​`Extract`​ / ​`Concat`​，注意与反编译里的 ​`>>`​、​`& 0xff` 一一对应。
- 有符号除法/取模用默认的 ​`/`​ ​`%`​；无符号必须换 ​`UDiv`​ ​`URem`，两者在负数区间结果完全不同。

```python
from z3 import *

a = BitVec('a', 8)
s = Solver()
s.add(UGT(a, BitVecVal(0x10, 8)), ULT(a, BitVecVal(0x80, 8)))
s.add(ZeroExt(8, a) * ZeroExt(8, a) == 0x1081)   # 0x41 * 0x41，提升到 16 位
print(s.model()[a])                              # 65
```

## 0x05 从 IDA 到 Z3 的固定流程

1. 定位校验函数和比较点：​`memcmp`​、​`strcmp`​、逐字节 ​`==`​、最后那个 ​`printf("right")` 分支。
2. 记录输入长度：​`strlen` 调用、循环上界、栈缓冲区大小，三个里取一致的。
3. 导出常量：立即数、目标数组、S-box 直接从 ​`.rdata` 复制，不要手打。
4. 用明文写 Python 复现版，喂一个已知输入，打印每个中间态。
5. 把输入替换成 ​`BitVec` 列表，逐行照抄运算，掩码和截断一个都别省。
6. 先只加一条约束跑 ​`sat`​，确认模型通了，再逐条加；每加几条就 ​`check()` 一次。
7. 解出来后回代原程序或复现版，输出 ​`right` 才算完成；只满足 flag 格式不算。

## 0x06 性能与可解性

- 能化简的常量先 ​`simplify()` 手算掉，别让求解器做无用功。
- 约束越早越强：长度、字符集、已知前缀、​`Distinct` 先写，剪枝效果最明显。
- 乘除法最贵；32 位乘法没问题，64 位以上尽量拆成多段或先降维。
- 大量 ​`If`​ 查表会拖慢甚至卡死，改用 ​`Array` 或分段求解。
- `s.set("timeout", 60000)`​ 必须有，避免无限等；​`unknown` 基本等于模型太大。
- 相互独立的约束分开求解，链式约束才需要放在同一个 solver 里。
- 还慢就换 ​`SolverFor("QF_BV")`​，或者用 ​`Then('simplify', 'bit-blast', 'sat')` 自己拼战术。

## 0x07 常见坑点

- 把 Python 的 ​`/`​ 当整除用，BitVec 上它是 ​`SDiv`。
- `Int`​ 不会自动溢出，​`BitVec` 会；两者混用会得到完全不同的解。
- 变量重名：​`BitVec('x', 32)`​ 调两次拿到的是同一个符号变量，批量生成一定带下标 ​`f{i}`。
- 打印模型不要直接 ​`str(m)`​，用 ​`m[x].as_long()`​ / ​`is_true(m[b])` 取值。
- `unsat` 不要盲改：注释掉一半约束做二分，先定位是哪一条写错。
- 模型出多解时不要以为解错了，是约束不够；加一条已知关系或换个字节继续解。
- 端序、符号扩展、​`memcmp` 长度三件事，抄错任何一件都只能得到"看起来像 flag"的垃圾。
- 有些题在比较前还会做 ​`base64`​ / ​`XXTEA` / 自定义 padding，先把外层剥掉再建 Z3 模型。
