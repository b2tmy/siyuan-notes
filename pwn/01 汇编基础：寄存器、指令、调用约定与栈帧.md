# 01 汇编基础：寄存器、指令、调用约定与栈帧

# 01 汇编基础：寄存器、指令、调用约定与栈帧

pwn 只看三样东西：数据放在哪（寄存器/栈/堆）、函数怎么拿参数（调用约定）、返回地址存在哪（栈帧）。看完这篇，应该能把 ​`objdump`​ 里 ​`main` 的十来行汇编和 C 代码逐行对上。

## 0x00 为什么先看汇编

- 溢出点要从汇编里确认：缓冲区在 ​`[rbp-0x20]`​，返回地址在 ​`[rbp+8]`​，偏移就是 ​`0x28`。
- 参数从哪个寄存器拿：​`read(0, buf, 0x100)`​ 编译出来是 ​`rdi=0, rsi=buf, rdx=0x100`。
- gadget 得自己找：​`pop rdi; ret` 就是两条指令，不会看汇编就不知道该搜什么。
- 崩溃现场要看：​`rip`​ 指向 ​`0x41414141`​，说明返回地址被 ​`A` 覆盖了，偏移刚好。

## 0x01 寄存器（x86-64）

|寄存器|低 32 位|约定用途|备注|
| ------------| ------------| --------------------------| -----------------------------|
|`rax`|`eax`|返回值 / 累加 / ​`syscall` 号|除法隐含使用|
|`rbx`|`ebx`|通用，callee-saved|被调用者保存|
|`rcx`|`ecx`|第 4 个参数 / 循环计数||
|`rdx`|`edx`|第 3 个参数 / 返回值高位||
|`rsi`|`esi`|第 2 个参数|源地址|
|`rdi`|`edi`|第 1 个参数|目的地址|
|`rbp`|`ebp`|栈帧基址||
|`rsp`|`esp`|栈顶|永远指向最后压入的数据|
|`r8`​–​`r9`|`r8d`​–​`r9d`|第 5、6 个参数||
|`r10`​–​`r15`||通用|`r10` 是第 4 个 syscall 参数|
|`rip`|`eip`|下一条指令地址|溢出改的就是它|

8 位视图：​`rax`​ 的低 16 位是 ​`ax`​，再拆成 ​`ah`​ / ​`al`​。32 位下 ​`eax`​ 写值会自动把 ​`rax` 高 32 位清零，这是常见的"高位被清"行为。

`rsp`​ 的规律：​`push`​ 让 ​`rsp -= 8`​，​`pop`​ 让 ​`rsp += 8`；栈从高地址向低地址生长。

## 0x02 指令速查

```asm
mov  dst, src       ; 赋值
movzx eax, byte [rdi] ; 零扩展搬运
movsx eax, byte [rdi] ; 符号扩展搬运
lea  rax, [rbp-0x20]  ; 取地址（不访问内存）
add/sub/imul/idiv     ; 算术
xor  eax, eax         ; 清零（比 mov eax,0 短）
and/or/not/neg        ; 位运算
shl/shr/sar           ; 左移 / 逻辑右移 / 算术右移
cmp  a, b             ; 做减法只改标志位
test a, a             ; 做与只改标志位，常用来判零
jmp/jz/jnz/jg/jl/jle  ; 跳转
call f                ; push 返回地址 + 跳转
ret                   ; pop 到 rip
leave                 ; mov rsp, rbp; pop rbp
push/pop              ; 压栈/出栈
syscall               ; 64 位系统调用
int 0x80              ; 32 位系统调用
nop / int3            ; 空操作 / 断点
```

条件跳转对应关系：​`cmp a, b`​ 之后，​`je`​ 是 ​`a == b`​，​`jg`​ 是 ​`a > b`​（有符号），​`ja`​ 是 ​`a > b`（无符号）。逆向时看错符号/无符号，逻辑就会理解反。

## 0x03 AT&T 与 Intel 语法

`objdump`​ 默认 AT&T（源在前、目的在后，寄存器带 ​`%`​），加 ​`-M intel` 更好读：

```bash
objdump -d -M intel ./vuln | less
gdb ./vuln -ex 'set disassembly-flavor intel' -ex 'disassemble main'
```

|操作|AT&T|Intel|
| --------| ------| -------|
|赋值|`mov %rsp, %rbp`|`mov rbp, rsp`|
|取地址|`lea -0x20(%rbp), %rax`|`lea rax, [rbp-0x20]`|
|内存写|`mov %eax, -0x8(%rbp)`|`mov dword ptr [rbp-8], eax`|
|立即数|`mov $0x100, %edx`|`mov edx, 0x100`|

看 ​`call`​ 后面的地址、​`lea` 算出来的缓冲区位置，是定位溢出点的关键。

## 0x04 调用约定

### System V AMD64（Linux x86-64）

- 整型/指针参数依次放：​`rdi`​、​`rsi`​、​`rdx`​、​`rcx`​、​`r8`​、​`r9`，第 7 个开始走栈。
- 返回值在 ​`rax`​（128 位时用 ​`rdx:rax`）。
- `rbx`​、​`rbp`​、​`r12`​–​`r15` 由被调用者保存；其余 caller-saved。
- `call`​ 之前 ​`rsp`​ 必须 16 字节对齐（进入函数时 ​`rsp % 16 == 8`​）。这就是为什么 ret2libc 里经常要垫一个 ​`ret`​ gadget——否则 ​`system`​ 里的 ​`movaps` 会崩。
- 栈下方 128 字节是 red zone，叶子函数可以不调整 ​`rsp` 直接用。

### cdecl（Linux x86-32）

- 参数从右往左压栈，调用者清理栈（​`add esp, 0x10`）。
- 返回值在 ​`eax`。
- 32 位下返回地址只有 4 字节，偏移计算和 x64 不同。

### Microsoft x64（Windows）

- 前四个参数：​`rcx`​、​`rdx`​、​`r8`​、​`r9`；调用者要在栈上预留 32 字节 shadow space。
- 和 Linux 的差别主要在第 1、4 个参数用 ​`rcx`​ 而不是 ​`rdi`，以及 shadow space。Windows 题看汇编时别套 SysV。

## 0x05 函数序言、结语与栈帧

```asm
push rbp            ; 保存调用者的 rbp
mov  rbp, rsp       ; 建立当前帧
sub  rsp, 0x40      ; 开局部变量空间
...
leave               ; mov rsp, rbp; pop rbp
ret                 ; pop rip
```

对应的栈布局（高地址在上）：

```text
+---------------------+  <- 调用者的栈
| 参数 7、8 ...        |
+---------------------+
| 返回地址             |  <- rbp + 8   ← 溢出要改的地方
+---------------------+
| saved rbp           |  <- rbp       ← 先被覆盖
+---------------------+
| 局部变量 / buf       |  <- rbp - 0x20 ... rbp - 1
+---------------------+
| ...                 |
+---------------------+  <- rsp
```

所以一个 ​`char buf[32]` 的溢出偏移是：

```text
32 字节 buf + 8 字节 saved rbp = 40 字节，第 41 字节开始就是返回地址
```

## 0x06 一段 C 到汇编

```c
long add(long a, long b) {
    long c = a + b;
    return c;
}
```

`gcc -O0` 编出来（Intel 语法，典型形态）：

```asm
add:
    push   rbp
    mov    rbp, rsp
    mov    [rbp-0x18], rdi      ; 第 1 个参数 a
    mov    [rbp-0x20], rsi      ; 第 2 个参数 b
    mov    rax, [rbp-0x18]
    add    rax, [rbp-0x20]
    mov    [rbp-0x8], rax       ; 局部变量 c
    mov    rax, [rbp-0x8]       ; 返回值
    pop    rbp
    ret
```

三个要点：

1. 参数先进寄存器，​`-O0` 下马上被存到栈上，所以栈里能看到参数副本。
2. 返回值一定在 ​`rax`​，​`ret`​ 之前不要动 ​`rax`。
3. `-O2`​ 会把这一堆优化成 ​`lea rax, [rdi+rsi]`，所以分析时优先看题目原始二进制，不要自己重编译对比。

## 0x07 系统调用

x86-64 用 ​`syscall`​，调用号放 ​`rax`​，参数依次 ​`rdi`​、​`rsi`​、​`rdx`​、​`r10`​、​`r8`​、​`r9`​，返回值在 ​`rax`。

|号|调用|参数|
| ----| ------| ------|
|0|`read`|`rdi=fd, rsi=buf, rdx=count`|
|1|`write`|`rdi=fd, rsi=buf, rdx=count`|
|2|`open`|`rdi=path, rsi=flags, rdx=mode`|
|3|`close`|`rdi=fd`|
|9|`mmap`|`rdi=addr, rsi=len, rdx=prot, r10=flags, r8=fd, r9=off`|
|10|`mprotect`|`rdi=addr, rsi=len, rdx=prot`|
|59|`execve`|`rdi=path, rsi=argv, rdx=envp`|
|60|`exit`|`rdi=code`|

32 位是 ​`int 0x80`​，调用号在 ​`eax`​，参数 ​`ebx`​、​`ecx`​、​`edx`​、​`esi`​、​`edi`​、​`ebp`​，​`execve` 是 11。

一段手写 ​`execve("/bin/sh", 0, 0)`：

```asm
xor  rdx, rdx
xor  rsi, rsi
lea  rdi, [rip+binsh]
mov  rax, 59
syscall

binsh:
    .ascii "/bin/sh\0"
```

pwn 里更常用 pwntools 生成：

```python
from pwn import *
context.arch = 'amd64'
shellcode = asm(shellcraft.sh())
print(len(shellcode), shellcode.hex())
```

## 0x08 编译与阅读

常用编译参数（做靶子时固定这套，方便对照笔记）：

```bash
gcc -O0 -fno-stack-protector -no-pie -z execstack -o vuln vuln.c
# 32 位
gcc -m32 -O0 -fno-stack-protector -no-pie -z execstack -o vuln32 vuln.c
```

- `-O0`：保留栈帧，变量不会被优化没。
- `-fno-stack-protector`：关 canary。
- `-no-pie`​：固定地址，方便写死 ​`win` 的地址。
- `-z execstack`：栈可执行，方便 ret2shellcode。

阅读顺序：

```bash
checksec --file=./vuln
objdump -d -M intel ./vuln | grep -A 30 "<main>:"
gdb ./vuln -ex 'b main' -ex run -ex 'info registers' -ex 'x/20gx $rsp'
```

pwndbg 里更直观：​`stack 20`​、​`telescope $rsp 20`​、​`vmmap`​、​`checksec`。

## 0x09 常见坑

- **看错语法**：AT&T 的 ​`mov %rsp, %rbp`​ 是 ​`rbp = rsp`，和 Intel 顺序相反。
- **x64 参数以为在栈上**：前 6 个在寄存器，栈上是第 7 个起；但 ​`-O0` 会把参数存回栈，别被误导。
- **32 位和 64 位混用**：返回地址宽度不同（4 / 8 字节），偏移和 gadget 都不能混。
- **​`lea`​**​ **当** ​**​`mov`​**​：​`lea rax, [rbp-0x20]`​ 是取地址，不是读内存内容；​`mov rax, [rbp-0x20]` 才是读值。
- **忽略栈对齐**：64 位调 ​`system`​ 前 ​`rsp`​ 不 16 字节对齐，会在 ​`movaps` 崩，现象是"明明地址对却拿不到 shell"。
- **​`syscall`​**​ **参数顺序**：第 4 个是 ​`r10`​ 不是 ​`rcx`​（​`syscall`​ 指令会覆盖 ​`rcx`）。
